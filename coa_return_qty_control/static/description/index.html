Core Capabilities

6 Feature Pillars That Protect Your Inventory

Every feature is built to be intuitive, automatic, and invisible until you need it — then it acts decisively.

🔒

Maximum Return Quantity Validation

The module calculates the total quantity delivered across all validated pickings for each product line and sets that as the hard upper limit. Any attempt to create a return exceeding this ceiling triggers a descriptive validation error that names the product and shows the allowed maximum.

Python ORM Override Validation Constraint
🔁

Real-Time "Already Returned" Counter

A computed field on the return wizard line aggregates all previously validated return moves for that product on the same origin picking. The value refreshes dynamically so that even mid-session partial returns are reflected before the user submits the current return.

Computed Field Real-Time Update
📋

"Remaining to Return" Display on Wizard

Directly on the return wizard dialog, users see a clearly labelled "Remaining to Return" column. This is the net returnable quantity: Delivered Qty minus Already Returned Qty. Users know instantly how much they can still return without needing to open another window or run a report.

Wizard View Extension Inline Display
📦

Delivery Order Quantity Summary

The delivery order (stock picking) form view is enhanced with three summary columns per product line: Delivered Qty, Already Returned Qty, and Remaining to Return Qty. Warehouse managers gain full visibility of the return status directly on the picking without navigating away.

Stock Picking View Summary Columns
🔄

Partial Delivery & Backorder Support

In workflows where an order is fulfilled across multiple deliveries (backorders), the module correctly sums quantities from all related done pickings. Each partial delivery's returnable window is respected independently, and the cumulative Already Returned figure accounts for returns across every shipment.

Backorder Aware Multi-Delivery
🏦

Inventory Accuracy Protection

By enforcing a firm ceiling on returnable quantities at the source, the module eliminates the root cause of negative stock levels and inflated inventory values. The protection works regardless of user permissions level, making it a reliable company-wide safeguard for accounting integrity.

Under the Hood

How the Validation Works

Three simple steps — from opening the wizard to submitting the return — with an iron-clad guard at every stage.

1

Open Return Wizard

Navigate to the completed delivery order and click the Return button. The module pre-populates the wizard with all product lines from the original picking.

Inventory > Delivery Orders > [Done] > Return
→
2

View Delivered vs Already Returned vs Remaining

Each wizard line now shows three read-only informational columns alongside the editable return quantity, giving users full context before they type anything.

Delivered 10.00
Already Returned 3.00
Remaining 7.00
→
3

Enter Qty — Blocked if > Remaining

The user types a return quantity. If it exceeds the remaining returnable amount, the system raises a ValidationError immediately upon clicking "Return", naming the product and the maximum allowed quantity.

⛔ Validation Error
"You cannot return more than 7.0 units of [Product A]. Already returned: 3.0"

The guard works server-side: The validation fires inside the _prepare_move_default_values() override, comparing the requested quantity against the net remaining ceiling before any database write occurs. This means the protection cannot be bypassed through the UI, the API, or any automation rule.

Frequently Asked Questions

Your Questions, Answered

Q

What happens if I try to return more than was delivered?

The system raises an Odoo ValidationError at the moment you click the "Return" button. The operation is cancelled entirely — no partial return record is created. The error dialog clearly states the product name, the quantity you attempted to return, the quantity already returned in previous sessions, and the maximum remaining quantity you are allowed to return.

⛔ The action is fully blocked — nothing is written to the database until the quantity is corrected.
Q

Does it support partial deliveries and backorders?

Yes, fully. The module is designed with multi-delivery workflows in mind. When an order is fulfilled across multiple shipments (backorders), the validation engine aggregates the done quantities from all related pickings for each product. Similarly, the "Already Returned" counter sums returns from every previous return picking tied to those deliveries, so the ceiling is always accurate even in complex multi-step fulfilment scenarios.

✅ Works correctly across all backorder and partial delivery combinations.
Q

Will it block legitimate returns that are within the delivered amount?

Absolutely not. The validation only triggers when the requested return quantity exceeds the net remaining returnable amount. Any valid return — including the full delivered quantity on a first return, or the exact remaining amount on a subsequent return — will pass without any interference. The module is designed to be invisible during normal, legitimate operations and only steps in to block genuine data-entry errors or intentional over-returns.

ℹ️ Returns at or below the remaining quantity are always allowed and processed normally.
