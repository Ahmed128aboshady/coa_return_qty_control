Stop Costly Warehouse Return Discrepancies

Standard Odoo allows warehouse operators to enter any arbitrary return quantity, making it easy to accidentally return more goods than delivered, corrupting stock valuation.

Without COA Return Quantity Control

  • Operators can enter return quantities exceeding what was actually delivered to customers.
  • Over-returns drive inventory quantities into negative numbers, corrupting valuation.
  • No visibility into previously returned quantities during RMA processing.
  • Billing teams issue incorrect credit notes based on inflated return records.

With COA Return Quantity Control

  • Hard validation blocks return submission if entered quantity exceeds delivered units.
  • Clear display on the return wizard: Delivered Qty, Already Returned, and Remaining Allowed.
  • Delivered vs Returned summary badges visible directly on stock picking records.
  • Guaranteed inventory valuation integrity across all RMA and reverse logistics flows.

Frequently Asked Questions

What happens if a user tries to return more items than delivered?

The module intercepts the wizard confirmation and displays an informative UserError stating the delivered quantity, amount already returned, and the maximum allowed return quantity.

Does it support partial returns across multiple return pickings?

Yes. If an order delivered 10 units and 3 were returned previously, the wizard automatically detects the 3 returned units and caps the remaining return limit at 7.

Does it interfere with standard Odoo return stock moves?

No. When valid quantities are entered, the standard Odoo return process executes with full scrap, location routing, and credit note compatibility.
